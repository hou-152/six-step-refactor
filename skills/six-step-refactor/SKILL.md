# six-step-refactor：重构六步法

把「重构一下」变成可复用、可回滚、可验收的动线。适用于有既有资产的 Skill 家族、知识库、Agent 体系等自维护系统；不适用于一次性脚本或从零新建（那是 dbs-skill-maker 的领域）。

## 顶端判据：逆熵

治理层（唯一真源、唯一认领、只追加、机检）只为服务层（把用户的无限选择压成唯一下一步、噪音压成漏斗、机械劳动交给授权脚本）存在。**不能减少用户难受的设计＝过度设计**——每个部件先过这一条再讨论去留。

## 六步流程

1. **编排定界**——复杂任务先进编排（1 主 ≤ 2 辅），出提示词不接手；授权边界动手前写清。
2. **体检取证**——真源全读、验收脚本全跑、证据分级（健康项保留／病灶点名）；结构性病灶要拿文件与日志实锤，且读到机制层：字段 ≠ 外发内容、报告结论 ≠ 执行函数，红级结论必须看发送/执行处。
3. **对标定案**——外部系统拆到机制层（门槛、判据、预算数字），加理论与历史同构成败案例，得出**条件性标准答案**；核心结论通常是「反大爆炸、分步可回滚」。
4. **方案拍板**——旧拍板与新架构的冲突列成 C 清单（C1…Cn），不静默沿用也不静默推翻，交所有者逐项定；**拍板前不动任何共享文件（硬检查点）**。
5. **绞杀者落地**——纯增量先行（契约＋字段＋机检脚本，让规则从文档变闸门）→ 行为级改动走门槛（窄假设＋正常/边界样本＋evals 留痕）→ 真实事件攒证据 → 观察期后由数据决定合并与砍除。ID 稳定、日志只追加、动手前快照＋逐文件 manifest。
6. **对抗闭环**——建成后自己攻击自己：第一性定价每个部件（知识-行动断裂？双真源漂移？零调用层？）；干净上下文盲测拿验证等级；与改前版本逐字节比对默认行为；审计结论本身可被机制证据修正——**诚实修正是方法的一部分，不是失败**。

## 五条铁律

1. **唯一真源＋唯一认领人**——多副本、多认领即 bug，机器可检（重复即 FAIL）。
2. **发前停**——产出要离开本机/账号就停在建议稿。
3. **验证分级如实报**——L1 结构 ≠ L2 行为 ≠ L3 真实；没跑行为只能报结构绿，「全绿」不等于「在工作」。
4. **失败驱动＋证据驱动**——修改必须解释一类稳定失败；拆分、合并、砍除都等使用数据（rollup 只出建议）。
5. **每步可回滚**——路径限定提交、快照、幂等脚本、绞杀者迁移；恢复先解包比对再选择性恢复。

## 停止条件

- 体检全绿且无失败证据时，结论就是「不重构」——反大爆炸本身就是标准答案。
- 拍板未回来前停在 C 清单，共享文件零改动。
- 安全门禁拦截时按其建议合规整改，不绕过、不代改安全工具状态。
- 修改开始依赖单个案例补丁时回炉重议。

## 完成条件与已验证案例

- 六步走完且每步留痕：C 清单已拍板、快照可回滚、验证等级如实报告、无失败证据时敢给出「不重构」结论。
- 2026-09-26 首次成文前两次实战：Skill 族触发语重构（70 条三段式弹药上线）与 fitness-kb v3→v3.1（体检 ✓48/✗0 → 只做检索域增量＋复核包；对抗闭环当轮抓出计数语义缺陷与验收过强措辞并修正，验收留痕在所有者本地库）。
